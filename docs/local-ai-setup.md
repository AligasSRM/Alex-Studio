# تشغيل المساعدة الذكية مجانًا باستخدام Ollama

يمكن تشغيل توليد المسودات محليًا دون مفتاح API أو رصيد مدفوع. هذا المسار يستخدم Ollama على نفس الجهاز الذي يشغّل خادم Alex Studio؛ لا يرسل ملفات المشروع إلى OpenAI.

## الإعداد

1. ثبّت Ollama من الموقع الرسمي: https://ollama.com/
2. نزّل نموذجًا مناسبًا، مثل:
   ```sh
   ollama pull qwen2.5-coder:7b
   ```
   يحتاج تنزيل النموذج إلى اتصال إنترنت ومساحة تخزين، وقد يحتاج إلى ذاكرة كبيرة. بعد تنزيله، يمكن أن يعمل محليًا دون دفع رسوم API.
3. شغّل Ollama وتأكد أن واجهته المحلية متاحة على `http://127.0.0.1:11434`.
4. شغّل Alex Studio من نفس الجهاز واضبط متغيرات البيئة التالية قبل تشغيل خادم Next.js:
   ```sh
   AI_PROVIDER=ollama
   OLLAMA_MODEL=qwen2.5-coder:7b
   ```
   لا حاجة إلى `OPENAI_API_KEY` في هذا الوضع.
5. أعد تشغيل خادم Alex Studio ثم جرّب توليد مسودة. تبقى الملفات الأصلية دون تغيير حتى تراجع المسودة وتوافق على تطبيقها.

## ملاحظات وحدود

- يظل التوليد بحاجة إلى موافقة صريحة، وتُطبّق عليه ضوابط المسارات وحجم الملفات الحالية.
- يسجل عداد التكلفة تكلفة التوليد المحلي على أنها صفر. قد تختلف السرعة والجودة بحسب النموذج وموارد الجهاز.
- الإعداد الافتراضي يتصل بـ `127.0.0.1` فقط؛ لذلك لا يعمل تلقائيًا إذا كان Alex Studio داخل حاوية Docker منفصلة عن Ollama على المضيف.
- عند عدم ضبط `AI_PROVIDER=ollama`، يبقى المسار الحالي لمزوّد OpenAI كما هو.
- اختبار CI يستخدم استجابة محلية وهمية للتحقق من تكامل Ollama دون الحاجة إلى تنزيل نموذج. يلزم تشغيل Ollama فعليًا على الجهاز لإثبات تشغيل النموذج المحلي الحقيقي.
