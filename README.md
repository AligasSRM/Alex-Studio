# Alex Studio

## القرار النهائي لنطاق المنصات

**Windows 10 + Android فقط**

- **Windows 10:** المضيف الوحيد لتشغيل Alex Studio، وإدارة المشاريع والملفات والنسخ الاحتياطية، والتنفيذ والاختبارات.
- **Android:** تطبيق مرافق للتحكم والاتصال بالمضيف، وإرسال الأفكار والمواصفات، ومراجعة الخطط والفروقات، وإعطاء الموافقات الصريحة.
- لا توجد أي منصة تشغيل أخرى ضمن المشروع. هذا القرار نهائي ولا يتغير إلا بقرار صريح جديد من مالك المشروع.

المرجع الملزم: [قرار نطاق المنصات](docs/decisions/PLATFORM-SCOPE-ANDROID-WINDOWS10.md).

## هدف المشروع

استوديو تطوير شخصي مدعوم بالذكاء الاصطناعي. يقبل فكرة أو وثيقة مواصفات، يفهم المطلوب، يضع خطة، يولّد مسودات متعددة الملفات، يعرض الفروقات، وينتظر موافقة المستخدم قبل تطبيق أي تغيير.

دورة العمل المستهدفة:

**فهم ← تخطيط ← توليد ← مراجعة ← موافقة ← تطبيق آمن ← اختبار ← تشخيص ← إصلاح محدود ← إعادة اختبار ← تسليم موثّق.**

## حدود الأمان

- لا يطبّق الذكاء الاصطناعي أي تعديل دون موافقة صريحة على المسودة الدقيقة.
- تُفحص المسارات وبصمات الملفات قبل أي عملية تعديل.
- تُحفظ أدلة التطبيق والنسخ الاحتياطية ونتائج التراجع.
- لا يُشغّل الكود المولّد مباشرة بصلاحيات المستخدم المضيف.
- إذا لم تتوفر آلية عزل أصلية وآمنة على Windows 10، تتوقف عمليات التنفيذ والاختبار وتظهر `UNAVAILABLE`.
- لا يُسمح بالوصول خارج مجلد المشروع، وتُرفض الروابط الرمزية ونقاط إعادة التوجيه غير الآمنة.

## الحالة التنفيذية الحالية

| المكوّن | الحالة |
|---|---|
| نطاق Windows 10 + Android | معتمد نهائياً |
| قراءة ملفات المشاريع | متاحة مع فحوص المسارات |
| كتابة الملفات وحذفها | محجوبة مؤقتاً حتى إثبات حماية Windows الأصلية |
| إنشاء المشاريع عبر API | محجوب مؤقتاً حتى اكتمال حماية التعديل |
| تنفيذ أوامر المشاريع المولّدة | `UNAVAILABLE` حتى توفير العزل الأصلي |
| فحص المتصفح ومعاينة الخادم | `UNAVAILABLE` حتى توفير العزل الأصلي |
| تطبيق Android على جهاز فعلي | يحتاج اختبار قبول فعلي |
| دورة الذكاء الاصطناعي الكاملة | غير مقبولة نهائياً بعد |

تفاصيل العائق الحالي: [Windows-native runner blocker](docs/reviews/WINDOWS-NATIVE-RUNNER-BLOCKER-2026-11-03.md).

## قواعد العمل على المستودع

- لا تعديل مباشر على `main`.
- العمل على فرع مستقل وطلب دمج منفصل.
- لا دمج قبل نجاح الاختبارات المطلوبة ومراجعة الأدلة.
- نجاح CI وحده لا يثبت قبول Windows 10 على الجهاز الفعلي أو قبول Android على الهاتف.
- لا تُسجّل أي خطوة غير منفذة على أنها ناجحة.

## معايير الإغلاق

لا يُغلق المشروع قبل إثبات:
1. عمليات الملفات الآمنة على Windows 10، بما فيها الحماية من reparse points وTOCTOU والكتابة الذرية والنسخ الاحتياطي والتراجع.
2. عزل أوامر المشاريع المولّدة، مع حدود الموارد والشبكة والمهلة وإنهاء شجرة العمليات والتنظيف.
3. تشغيل المعاينة واختبارات المتصفح ضمن العزل الآمن.
4. تثبيت Android والاقتران والاتصال والتعامل مع انقطاع الاتصال وإلغاء الجلسة.
5. دورة كاملة موثقة من الفكرة حتى التسليم، مع نتائج الاختبارات الفعلية.

**الحالة الحالية:** العمل مستمر. اعتماد نطاق المنصات لا يعني أن جميع وظائف Windows 10 وAndroid مكتملة أو مقبولة للإصدار.
